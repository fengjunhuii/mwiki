# /html-analyze 命令详解

## 执行流程

### 1. 读取文件
使用 Read 工具读取用户指定的 Markdown 文件。

### 2. 结构分析

#### 识别元素
- `#` 标题 → 分段标题
- `##` 二级标题 → 分区标题
- `###` 三级标题 → 卡片标题
- `-` 列表 → 要点列表
- `>` 引用 → 引用块
- ``` ``` 代码块 → 代码区
- `**粗体**` → 强调文字
- `*斜体*` → 次要文字

#### 提取数据
- 数字 + 单位 → 统计数据
- URL → 链接资源
- 图片路径 → 媒体资源

### 3. 分段策略

```
文档结构映射：

# 主标题           → hero 区（首屏）
   简介段落        → hero 区副标题

## 第一章          → section（标题 + 内容）
   ### 要点1       → card
   ### 要点2       → card
   - 列表项        → card 内容

## 第二章          → section
   > 引用          → quote 区
   ```代码```      → code 区

## 总结            → ending 区
```

### 4. 输出格式

```markdown
## 文稿分析结果

### 文档信息
- **标题**: [文档标题]
- **总分段数**: [N]
- **预估阅读时间**: [X] 分钟

### 分段清单

#### 分段 1: Hero 区
- **类型**: hero
- **标题**: [主标题]
- **副标题**: [简介]
- **关键词**: [关键词列表]

#### 分段 2: 数据统计
- **类型**: stats
- **数据项**:
  - 1902: 源码文件数
  - 47.7万: 代码行数
  - 6: 内置Agent数

#### 分段 3: 核心能力
- **类型**: cards
- **卡片数量**: 3
- **卡片内容**:
  1. 提示词动态拼装
  2. Agent分工调度
  3. 工具安全管线

...

### 建议调整
- [可选的优化建议]
```

## 用户交互

分析完成后，询问用户：
1. 是否需要调整分段结构？
2. 是否需要合并/拆分某些分段？
3. 确认后进入设计阶段

## 示例

**输入**：
```markdown
# 产品发布

## 核心数据
- 日活用户 1000万
- 营收增长 200%

## 新功能
- AI 助手
- 云同步
```

**输出**：
```
文稿分析结果

文档信息:
- 标题: 产品发布
- 总分段数: 3
- 预估阅读时间: 2 分钟

分段清单:

分段 1: Hero 区
- 类型: hero
- 标题: 产品发布
- 副标题: (无)

分段 2: 数据统计
- 类型: stats
- 数据项:
  - 1000万: 日活用户
  - 200%: 营收增长

分段 3: 新功能
- 类型: cards
- 卡片数量: 2
- 卡片内容:
  1. AI 助手
  2. 云同步

建议: 可考虑添加 ending 区进行总结
```
