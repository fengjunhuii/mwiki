# PRD 质量检查清单

完成 PRD 后，以四个角色视角进行全面检查。

---

## 1. 技术负责人视角

从技术实现难度、系统性能、安全风险角度审视。

### 检查项
- [ ] 并发处理：高峰期如何保证系统稳定？
- [ ] 幂等性：重复提交如何处理？
- [ ] 异常恢复：网络断开、支付中断如何处理？
- [ ] 数据一致性：分布式场景下如何保证？
- [ ] 安全防护：SQL 注入、XSS、CSRF 如何防范？
- [ ] 性能瓶颈：大数据量查询如何优化？
- [ ] 扩展性：功能模块是否可独立扩展？
- [ ] 技术可行性：所有功能是否有明确的技术实现方案？

### 典型问题
> "如果用户在支付过程中网络断开，订单状态如何处理？是否有幂等性设计？"

---

## 2. 挑剔用户视角

从操作便捷性、流程合理性角度审视。

### 检查项
- [ ] 操作步骤是否过多？能否减少点击次数？
- [ ] 表单字段是否过多？能否智能填充？
- [ ] 错误提示是否友好？用户能否理解？
- [ ] 加载状态是否清晰？用户是否知道在等待？
- [ ] 撤销/回退是否方便？
- [ ] 首次使用是否有引导？
- [ ] 核心路径是否顺畅？有没有不必要的跳转？

### 典型问题
> "为什么修改收货地址要跳转三个页面？能不能在订单确认页直接编辑？"

---

## 3. 运营负责人视角

从数据分析、营销推广角度审视。

### 检查项
- [ ] 埋点设计：关键行为是否有埋点？
- [ ] 转化追踪：营销活动效果如何评估？
- [ ] 用户分层：如何区分不同价值用户？
- [ ] 运营工具：是否有足够的后台配置能力？
- [ ] 数据导出：运营报表如何生成？
- [ ] 推送触达：是否有消息通知机制？
- [ ] 分享裂变：是否有社交传播机制？

### 典型问题
> "是否有用户行为埋点？如何追踪营销活动的转化效果？"

---

## 4. 测试工程师视角

从异常场景覆盖角度审视。

### 检查项
- [ ] 边界值：最大/最小/空值如何处理？
- [ ] 并发操作：多人同时操作同一数据？
- [ ] 网络异常：弱网、断网、超时？
- [ ] 设备兼容：不同屏幕、浏览器、系统？
- [ ] 权限边界：越权操作是否被拦截？
- [ ] 数据隔离：多租户数据是否隔离？
- [ ] 输入校验：特殊字符、SQL 注入、XSS？
- [ ] 状态流转：所有状态流转是否合法？

### 典型问题
> "如果用户重复点击提交按钮会怎样？是否有防重复提交机制？"

---

## 5. 文档完整性检查

### 方向层
- [ ] 有明确的目标用户和核心痛点
- [ ] 有清晰的一句话产品定位
- [ ] 有明确的产品形态及选型理由
- [ ] 有商业价值或变现逻辑
- [ ] 有明确的「不做什么」边界

### 结构层
- [ ] 有核心用户动线（流程图或文字描述）
- [ ] 有结构化功能清单（带优先级）
- [ ] 有关键页面布局线框图
- [ ] 每个核心功能有独立详细描述

### 细节层
- [ ] 每个交互元素列出全部状态
- [ ] 边界条件已覆盖
- [ ] 有交互细节（操作反馈、危险操作确认等）
- [ ] 有数据规范（字段名、类型、长度、必填、默认值）
- [ ] 有面向终端用户的文案规范
- [ ] 文案规范与开发文档分开

---

## 6. 原型 UI 质量检查

交付原型前验证视觉、交互、主题适配和无障碍性。

### 视觉质量
- [ ] 不使用 emoji 作为图标（使用 SVG）
- [ ] 所有图标来自统一图标库（Heroicons / Lucide）
- [ ] Hover 状态不会导致布局偏移
- [ ] 使用语义化主题色（`bg-primary`）
- [ ] 间距和字号遵循设计系统规范

### 交互反馈
- [ ] 所有可点击元素有 `cursor-pointer`
- [ ] Hover 状态提供清晰视觉反馈
- [ ] 过渡动画平滑（150-300ms）
- [ ] 键盘导航时焦点状态可见
- [ ] 表单输入有实时校验反馈

### 亮/暗模式适配
- [ ] 亮色模式文字有足够对比度（4.5:1 最低）
- [ ] 玻璃/透明元素在亮色模式下可见
- [ ] 边框在两种模式下都可见
- [ ] 图片和图标在两种模式下都清晰

### 无障碍
- [ ] 所有图片有 alt 文本
- [ ] 表单输入有 label
- [ ] 颜色不是唯一的指示器
- [ ] 尊重 `prefers-reduced-motion`
- [ ] 可通过键盘完成核心操作

---

## 检查输出格式

```markdown
## 质量检查报告

**总体评分：** X / 10
**一句话评价：** [概述]

### 技术风险
1. [问题描述] → 建议：[解决方案]

### 用户体验
1. [问题描述] → 建议：[解决方案]

### 运营需求
1. [补充需求] → 建议：[实现方案]

### 测试要点
1. [测试场景] → 预期：[预期结果]

### 文档缺失
1. [缺失内容] → 建议：[补充方向]

### UI 问题
1. [问题描述] → 修复：[修复方案]
```
