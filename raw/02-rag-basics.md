# RAG（检索增强生成）基础

## 概述

RAG（Retrieval-Augmented Generation）是一种将信息检索与大语言模型生成相结合的技术架构。它通过在生成回答前先检索相关文档，有效缓解 LLM 的幻觉问题和知识过时问题。

## 工作流程

1. **文档索引**：将知识库文档切分为 chunk，通过向量嵌入模型转换为向量，存入向量数据库
2. **查询检索**：用户提问时，将问题转换为向量，在向量数据库中检索最相关的文档片段
3. **上下文注入**：将检索到的文档片段作为上下文拼接到 prompt 中
4. **生成回答**：LLM 基于检索到的上下文生成回答

## 核心组件

### 向量嵌入模型
将文本转换为高维向量表示。常用模型：
- OpenAI text-embedding-ada-002
- BGE (BAAI General Embedding)
- E5 (Embedding learning for Everyone)

### 向量数据库
存储和检索向量。常用方案：
- ChromaDB
- Pinecone
- Milvus
- FAISS（Facebook AI Similarity Search）

### 文档切分策略
- 固定长度切分（如 512 tokens）
- 按段落/章节切分
- 语义切分（基于语义边界）

## 优势

- 减少 LLM 幻觉：基于真实文档生成回答
- 知识实时性：更新知识库即可获得最新信息
- 可追溯性：可引用具体来源文档
- 降低成本：无需重新训练模型

## 挑战

- 检索质量直接影响回答质量
- 文档切分粒度需要调优
- 多跳推理场景下效果有限
- 向量相似度不等于语义相关度

## 与 Fine-tuning 的对比

| 维度 | RAG | Fine-tuning |
|------|-----|-------------|
| 知识更新 | 实时 | 需要重新训练 |
| 成本 | 较低 | 较高 |
| 可解释性 | 强（可引用来源） | 弱 |
| 适用场景 | 知识密集型任务 | 风格/格式适配 |
