# /wiki-query — 知识查询

用户输入自然语言问题，Agent 从 `wiki/` 中检索并返回结构化答案。支持两种模式：**完整查询**（默认）和**快速查询**（`quick answer` 前缀）。

> **数据安全约束**：`_raw/` 和 `raw/` 仅作为来源参考，查询不修改任何文件。

---

## 前置准备

1. 读取 `ai/_index.json` 确认路由配置（`routes.query.quick` → `wiki/index.md`，`routes.query.full` → `wiki/concepts/`）
2. 确认 `wiki/index.md` 存在且可读
3. 如果 `wiki/index.md` 不存在或为空模板，输出「知识库尚未初始化或未导入素材，请先执行 /wiki-setup 和 /wiki-ingest」并终止

---

## 模式判断

根据用户输入判断查询模式：

| 输入形式 | 模式 | 说明 |
|----------|------|------|
| `/wiki-query quick answer <问题>` | 快速查询 | 仅读 `wiki/index.md`，不读 body |
| `/wiki-query <问题>` | 完整查询 | 读 index 定位 + 读概念页 body |
| `/wiki-query`（无参数） | 引导 | 提示用户输入问题 |

---

## 快速查询模式（quick answer）

仅读取 `wiki/index.md`，不读取 `wiki/concepts/*.md` 的 body 内容。

### 流程

1. **读取 `wiki/index.md`**：解析概念表格，提取所有已收录的概念名、标签、状态
2. **关键词匹配**：将用户问题中的关键词与概念名、标签进行匹配
   - 精确匹配：问题中包含概念名（不区分大小写）
   - 标签匹配：问题中包含某概念的标签关键词
   - 别名匹配：检查概念名是否有常见的同义词/缩写形式
3. **生成简要答案**：基于 `wiki/index.md` 中的表格信息（概念名、标签、来源数），生成一段简要回答
4. **输出结果**

### 快速查询输出格式

```
🔍 快速查询：[用户问题]

命中概念：N 个
  - [[概念A]] — tag1, tag2（来源数: 3）
  - [[概念B]] — tag3（来源数: 1）

简要回答：
  [基于 index 表格信息的简要说明，1-3 句话]

💡 提示：使用 /wiki-query [问题] 获取完整答案
```

### 无命中处理

如果没有匹配到任何概念：

```
🔍 快速查询：[用户问题]

未找到相关概念。

相近概念建议：
  - [[概念X]]（相似度: 标签重叠）
  - [[概念Y]]（相似度: 名称相近）

💡 建议：检查拼写或尝试更通用的关键词
```

相近概念的查找策略：
1. 从用户问题中提取核心名词
2. 在概念名列表中查找编辑距离 ≤ 3 的近似匹配
3. 在标签列表中查找部分重叠的概念
4. 最多返回 3 个建议

## 完整查询模式

先读 `wiki/index.md` 定位相关概念，再读对应 `wiki/concepts/*.md` 的完整内容，返回聚合的结构化答案。

### Step 1: 概念定位

1. **读取 `wiki/index.md`**：解析所有概念表格
2. **多维度匹配**：

   | 匹配维度 | 方法 | 权重 |
   |----------|------|------|
   | 概念名精确匹配 | 问题文本包含概念名 | 高 |
   | 概念名部分匹配 | 概念名是问题中某个词的子串 | 中 |
   | 标签匹配 | 问题的关键词出现在概念的标签中 | 中 |
   | 别名匹配 | 问题的关键词是概念的常见别名 | 中 |
   | 语义关联 | 问题与概念属于同一领域（如都涉及 AI） | 低 |

3. **筛选**：按匹配权重从高到低排序，取前 **5 个**最相关概念
4. **输出定位结果**：`定位到 N 个相关概念：[[概念A]], [[概念B]], ...`

### Step 2: 深度阅读

对 Step 1 筛选出的概念，逐一读取其 `wiki/concepts/*.md` 完整内容：

1. **读取概念页**：解析 frontmatter（title、tags、sources、summary）和 body 各章节
2. **提取相关段落**：从 body 中筛选与用户问题最相关的段落
   - 优先匹配 `## 定义` 和 `## 核心要点` 章节
   - 其次匹配 `## 应用场景` 和 `## 局限性` 章节
   - 保留 `## 相关概念` 中的 wikilink 用于交叉引用
3. **交叉扩展**（可选）：如果某个相关概念页的 `## 相关概念` 中包含其他高度相关的 wikilink，且该概念也在 Step 1 的候选列表中，一并读取
4. **控制 token 消耗**：所有读取的概念页 body 总量不超过 **4000 字**。如果超过，优先保留高权重概念的段落

### Step 3: 答案聚合

将 Step 2 提取的信息聚合为结构化答案：

1. **组织答案结构**：

   ```
   ## [直接回答段落]
   [基于概念定义和核心要点的直接回答，2-5 段]

   ## 来源篇章
   - [[概念A]] — 来源: source1.md, source2.md
   - [[概念B]] — 来源: source3.md

   ## 相关概念
   - [[概念C]]（关系说明）
   - [[概念D]]（关系说明）

   ## 扩展阅读
   - [[概念E]] — 与查询相关的延伸知识
   ```

2. **引用原文**：答案中引用概念页的具体内容时，使用 `> 引用内容` 格式并标注来源
3. **wikilink 链接**：所有提到的概念均使用 `[[概念名]]` 格式，便于在 Obsidian 中跳转

### 完整查询输出格式

```
📝 完整查询：[用户问题]

定位概念：N 个 → 深度阅读 M 个概念页

---

[结构化答案，包含定义、要点、场景等]

---

📊 查询统计：
  命中概念：N 个
  阅读页面：M 个
  来源篇章：K 篇
  相关概念：J 个

📎 原文链接：
  - [[概念A]]
  - [[概念B]]
  - [[概念C]]
```

### 无命中处理

如果 Step 1 未定位到任何概念：

```
📝 完整查询：[用户问题]

未找到相关概念。

相近概念建议：
  - [[概念X]] — 相似度说明
  - [[概念Y]] — 相似度说明

💡 建议：
  1. 检查拼写或尝试更通用的关键词
  2. 使用 /wiki-ingest 导入更多素材
  3. 使用 /wiki-lint 检查知识库完整性
```

---

## 响应时间控制

- **快速查询**：目标 < 5 秒（仅读 1 个文件）
- **完整查询**：目标 < 30 秒（读 index + ≤ 5 个概念页）
- 如果概念页读取耗时过长，减少读取数量并提示用户

## 查询日志

每次查询完成后，在 `wiki/log.md` 中追加记录：

```markdown
## YYYY-MM-DD HH:mm

- **操作**：`/wiki-query`
- **模式**：完整查询 / 快速查询
- **问题**：[用户问题]
- **命中概念**：N 个（列出概念名）
- **阅读页面**：M 个（完整查询时）
```

---

## 约束与安全

- 查询操作**不修改**任何 wiki/ 文件（除 wiki/log.md 追加日志外）
- `_raw/` 和 `raw/` 不直接参与查询，仅作为概念页的来源追溯
- 所有文件 UTF-8 无 BOM 编码
- 答案中引用的内容必须标注来源 wikilink
- 未命中的情况必须提供建议，不能只返回空结果
